# Epics and stories

This project plans in three levels: the product vision, epics (`docs/epics/`), and stories. A story is an ordinary Kiro spec.

- Epic first, then story. When the user starts any new spec, load the `story` skill and ask its first question before the other spec questions: which epic the work belongs to, an existing one, a new one, or none. Do all of this in the current session. Never open a new session or start a second spec workflow for it.
- To write or change an epic, follow the `epic-page` skill.
